# 漢字部件分色：通用原則

目前管線的問題不是「演算法不夠好」，而是**演算法與手寫資料混在一起**：
49 個字各有手畫部件矩形、3 個字有 `spans`、2 個字（思、湖）有 `HARD` 界線補丁。
每次出錯都只能針對那個字再加一條規則，所以永遠補不完。

要把錯誤從「逐字修」變成「結構上不可能發生」，需要六條不變量（invariant），
再加一個會自動失敗的檢查器。

---

## 六條不變量

### P1　筆畫是唯一的著色單位
顏色 = f(筆畫)，不可用像素位置決定。
→ 一筆永遠一色（已達成：`label_img = part_of[owner]`）。

### P2　部件 = 筆畫的集合，且部件之間是「分割」
每一筆恰好屬於一個部件，`part_of` 是完整映射、無重疊。
→ 部件之間不會出現「同一筆的兩半分屬兩件」。
這是 P1 的推論：只要 `part_of` 正確，一筆一色、一件不混色同時成立。

### P3　部件的領地 = 其筆畫的最近中心線（Voronoi）
一個像素屬於「中心線最近的那一筆」的部件，而不是屬於「哪個矩形框住它」。
→ 領地天然不相交、不自相矛盾；不需要手畫矩形。

### P4　分界線只可落在空白走廊或筆畫交叉點
由字形的投影剖面（projection profile）找空白帶決定：
上下結構找最寬的水平空白列帶，左右／左中右找垂直空白列帶，位置取「接近預期軸的最寬空白」。
→ 不會出現一條切在筆畫中間的直線（現時 `0.48`、`0.30` 這類硬編碼數字）。

### P5　幾何聽字型，身分聽筆畫資料
源流明體的筆形與 hanzi-writer 的輪廓必然有偏差（思的田角、湖的提尖就是這樣出錯）。
規則：
- **身分**（這一筆屬哪件）以 stroke 資料 + 結構為準；
- **幾何**（這一筆實際畫到哪裡）以字型墨跡為準。
兩者衝突時，字型贏幾何、筆畫資料贏身分，衝突處由 P3 的 Voronoi 決定歸屬。

### P6　輸出不得製造接縫
3–4× 超取樣渲染，降取樣用**最近色**（nearest colour），不可用雙線性／LANCZOS 混色。
→ 現時要靠 `binary_opening` 清 2–4px 髮絲接縫，若源頭不混色，這一步可以整條刪掉。

## 各結構的切法（由 P3+P4 自動推導）

| 結構 | 分界 | 自動判準 |
|---|---|---|
| 獨體字 | 無 | 全部筆畫屬同一件 |
| 左右 | 1 條垂直走廊 | 剖面最大空白列，位置 ∈ (0.35, 0.65) |
| 左中右 | 2 條垂直走廊 | 兩條最大空白列，把字分三段 |
| 上下 | 1 條水平走廊 | 剖面最大空白列，位置 ∈ (0.30, 0.70) |
| 上中下 | 2 條水平走廊 | 同上取兩條 |
| 品字形 | 上 1 / 下 2 | 先水平走廊，再下半部垂直走廊 |
| 全包圍 | 外框 vs 內件 | 外框筆畫＝首筆＋末筆（或 `radStrokes` 中含 4 個轉角的筆） |
| 三面包圍 | 外框 vs 內件 | `radStrokes` 的連通筆組 vs 其餘 |
| 兩面包圍 | 包圍筆 vs 內件 | 同上 |

包圍類不需空白走廊，直接用「哪幾筆構成框」判定（`radStrokes` 已足夠）。

---

## 檢查器（真正讓其他字不出錯的東西）

每次建置後對 49 字自動跑，任何一項 > 0 就 fail，並指出字與位置：

1. **一筆多色**：`max over strokes (#distinct parts in stroke ink) == 1`
2. **部件異色**：部件領地內「非本色」像素數 == 0（以 P3 領地計，非矩形）
3. **接縫**：任一顏色的 `opening(3×3)` 損失像素 == 0（現時 9227 px／輪，應可降到 0）
4. **孤島**：任一顏色的獨立連通塊數 > 部件數 → 有碎片
5. **覆蓋**：墨跡總像素 == 各部件像素和（無漏色、無黑洞）

第 5 項現在完全沒有檢查，是潛在的「黑洞」風險。

---

## 落地順序（建議）

1. 用 P4 自動求分界線，取代 49 組手寫矩形（矩形只留作 hint）。
2. 用 P2+P3 生成 `part_of`，刪掉 `spans`（3 字）與 `HARD`（2 字）。
3. 改超取樣 + 最近色降取樣（P6），刪掉 `clean_final` 的接縫／碎片兩道補丁。
4. 加入檢查器，CI 式跑，任何字不合格就印出字與失敗項。
5. 以現時 49 張圖作 baseline 做 A/B，逐字比對，確認沒有回歸。

預期結果：新增字只需提供 `(字, 結構, 部首)` 三元組，其餘全自動。

## 2026-10-26：切換失敗的覆核，與新的驗收方法

上次的「已切換」記錄只有一個結論可信：**通用管線能讓「一筆一色」成立**。
但「49/49 合格、異色 0.00%」這個說法**不能作為發佈依據**，原因有兩個。

### 問題一：原本的驗收指標是循環論證

`audit.py` 用 `part_of` 定義每一筆的領地，再量「領地內有沒有別色」。
`render()` 又是用同一個 `part_of` 上色，所以兩邊必然一致——它只能證明
「顏色跟 `part_of` 一致」，不能證明「`part_of` 正確」。實測：把通用管線的輸出
拿去跑審核，異色一律 0.00%；但同一個輸出裡，「湖」的「古」只剩 1 筆（其餘 4 筆
被判給「月」），「籃」的「監」有 7 筆被判給「竹」。

### 問題二：`assets/` 從來沒有被新管線重建過

`557b966`（切換）與 `431f8d9`（記錄結果）只改了 `_src/` 與 `_data/geom/*.npz`，
`assets/chars/*.png` 最後一次改動是 `5219087`。也就是說**線上 49 張圖仍是舊管線
的產物**（舊管線 88 筆多色、平均異色 10.70%）。換句話說，發佈與否當時並未發生。

### 新的驗收：以「已驗收圖」為語意基準

已上線的 49 張圖是用家看過、逐字修過的版本，是現階段唯一的語意真值。
新增三支工具（全部不看 `part_of` 當裁判）：

| 工具 | 作用 |
|---|---|
| `_src/pngmap.py` | 成品 PNG ↔ 字型墨跡座標的嚴格對映（按 alpha bbox 對齊，舊圖 800×800 只佔 83%、新圖 1000×1000 佔 77%，整圖縮放會錯位 10–17%） |
| `_src/verify.py` | 純度：一筆多色、未著色、顏色數；只看字型筆畫幾何＋像素顏色 |
| `_src/compare.py` | 兩組圖逐字逐筆比對：換色筆（語意變化）、混色筆（接縫）、像素差 |
| `_src/regress.py` | 自動分組 vs 已驗收圖的逐筆差異（抓「自動分組錯在哪個字」） |
| `_src/identity_lock.py` / `_src/lock_repair.py` | 把已驗收圖的身分鎖成 `identity.json`，再用 `radStrokes` 修掉舊圖殘留的單筆錯色 |
| `_src/publish_auto.py` | 把管線輸出寫入 `assets/` 並重建 `index.html`（含 content-hash 版號） |

### 未解決：色彩分區的兩種策略各有代價

- **最近中心線（Voronoi）**：一筆一色成立，但兩筆相鄰處會互相切邊。
  「湖」的提右側會被判給「古」，出現藍色楔形（見 `_preview/zoom_湖_old_new.png`）。
- **走廊帶（lane_owner）**：貼近舊圖的觀感，但分界線會把跨帶的筆切成兩色，
  實測混色筆 70（舊圖 66），沒有改善。

換言之：**只要筆畫歸屬仍然用「最近中心線」近似，這兩種症狀是同一枚硬幣的兩面**。
要同時解決，需要逐筆的**真實外形**（而不是中心線）——`parts_auto.stroke_own()`
已經用 hanzi 輪廓填色做了一半，但 hanzi 輪廓與源流明體的筆形有偏差（輪廓會蓋到
鄰筆的墨跡上，例如古的橫蓋住提），需要一個「逐筆外形到字型墨跡」的配準步驟。

### 下一步（建議）

1. 逐筆外形配準：對每一筆單獨求 (scale, dx, dy)，使該筆輪廓與字型墨跡的
   重疊最大化（而不是用全局仿射），再把輪廓內的墨跡判給該筆。
2. 有了可靠 `own` 之後，`part_of` 可以用「筆畫重心 + 走廊硬約束」求，
   顏色直接用 `part_of[own]`，兩個症狀就可以同時消失。
3. 新字（無已驗收圖）需人工確認一次身分，再把結果寫入 `identity.json`。

### 追加（同日）：四條路線的實測，以及根因

| 方案 | 混色筆 | 逐筆換色 | 結論 |
|---|---|---|---|
| 已驗收圖（線上） | 54–61 | — | 雙線性降取樣造成的接縫 |
| 最近中心線 + 逐筆輪廓（v7/v10/v11） | **1** | **3** | 湖出現藍色楔形 |
| 走廊帶分區（v8） | 70 | 5 | 跨帶的筆被切成兩色 |
| 逐筆外形配準（v9，面積對齊） | 83 | 3 | 配準目標來自 Voronoi，錯誤被放大 |
| 逐筆外形配準（`register.py`，遮擋懲罰） | — | — | 最優解全部落在搜尋格邊界，目標函數不成立 |
| 沿用舊分區重上色（`reskin.py`） | 61 | 0 | 舊圖接縫像素本身無色可比對，填不回去 |
| 標籤多數濾波（9×9×2） | 1 | 3 | 楔形太寬（>10px），濾波吸不掉 |

**根因**：hanzi-writer 的筆畫外形是**另一套字體**。以「湖」為例，hanzi 的「古」第一筆
（橫）起點在 x≈109（整個字寬 1024 的 10%），而源流明體的「古」橫起點約在 x≈330。
所以「古」的輪廓必然覆蓋「提」的墨跡，任何只靠輪廓的歸屬方法都會在該處切出楔形。
（附帶：`svg_polys` 與 `medians` 的座標框架其實一致，兩者 y 範圍同為 −18..844，先前
懷疑的翻轉錯位不成立。）

**下一步（唯一還沒試、且方向正確的一條）**：不要用輪廓決定歸屬，改用**墨跡內部的
測地分水嶺**——以 `medians` 貼合後的核心為種子，在字型墨跡上做 watershed
（`skimage.segmentation.watershed(-ink_distance, markers, mask=ink)`）。
它尊重墨跡連通性，會在兩筆相接的**窄頸**處切開，正是 P4 說的「分界線只可落在
空白走廊或筆畫交叉點」。這樣「一筆一色」與「部件歸屬」可以同時成立，而且不依賴
hanzi 的筆形。
